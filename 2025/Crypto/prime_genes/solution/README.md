# Prime Genes &mdash; Solution

In this challenge, inspired by a [paper](https://ieeexplore.ieee.org/document/9597026) published at a [local scientific conference](https://mipro.hr/), we are dealing with an RSA cryptosystem where the prime numbers have been generated using a genetic algorithm. Despite the claims in the paper, turns out that generating prime number for cryptography in this specific way is a bad idea.

We are given a script that generates 20 RSA keys (with primes generated by the same invocation of the algorithm in the paper) and encrypts the flag with each key. We are also given the output of the said script.
```python
#!/usr/bin/env python3

import math
import secrets

from Crypto.Util.number import *

from redacted import FLAG

PM = 0.05

def genetic_prime_gen(target_size_bits):
    population = ['10', '11', '101']
    number_large = 0
    while True:
        a, b = secrets.choice(population), secrets.choice(population)
        # Crossover
        child = a + b
        if secrets.randbelow(100) < PM*100:
            # Mutation
            x = secrets.randbelow(len(child))
            child = child[:x] + ('1' if child[x] == '0' else '0') + child[x+1:]
        if isPrime(int(child, 2)) and child not in population:
            if len(child) > target_size_bits:
                number_large += 1
            population.append(child)
        if number_large >= 2:
            break
    population.sort(key=lambda x: len(x), reverse=True)
    return population[0], population[1]


for i in range(20):
    p, q = genetic_prime_gen(512)
    p = int(p, 2)
    q = int(q, 2)
    N = p*q
    e = 65537
    c = pow(bytes_to_long(FLAG), e, N)
    print(f'{N=}')
    print(f'{e=}')
    print(f'{c=}')
    print()
```

Turns out that, in an arbitrary run, we get keys where (binary representations of) $p$ and $q$ have lots in common. For example, all of these cases appear with decent probability:
1. $q$ is a prefix of $p$ (like in the line 17 above),
2. $q$ is a suffix of $p$ (no such luck in this particular run),
3. $p$, and $q$ have a large common suffix (like in the line 6 above),
4. $p$, and $q$ have a large common prefix (no such luck in this particular run),
5. $p$ and $q$ have a large common substring (like in the lines 4 and 14 above).

In all these special cases, RSA can be broken by various methods. The problem is, of course, that we have no idea what exactly is in the output we are given. The intended approach was to try cases above, in the increasing order of difficulty, until we manage to successfully decrypt the flag.

Both cases 1 and 2 above can be solved fairly easily, but they were not present in the challenge input. Case 3 (large common suffix) was present, and the rest of this writeup is focused on that.

When $p$ and $q$ have the last $k$ bits in common, and $k$ is large (say more than half the size of $q$ in this case) it can be found in two steps:
1. Recover the candidates for the shared suffix by finding square roots of $N$ modulo $2^k$.
2. Recover the high bits of $q$ using the [Coppersmith's attack](https://en.wikipedia.org/wiki/Coppersmith%27s_attack).

Square roots can be found by simple breadth-first-search algorithm based on [Hensel lifting](https://en.wikipedia.org/wiki/Hensel%27s_lemma) -- which, in this particular scenario, is just fancy way of saying that each square root of $N$ modulo $2^k$ is obtainable by prepending a bit to some square root of $N$ modulo $2^{k-1}$.

The remaining issue is parameter selection for Coppersmith: since the exact bit-lengths of $p$ and $q$ and the suffix length $k$ are unknown, we can’t tune Coppersmith precisely. Model solution sweeps plausible ranges for these values and runs the attack with the corresponding $\beta$ and bounds.

Putting it all together:
```python
#!/usr/bin/env python3

from math import gcd
from Crypto.Util.number import *
from sage.all import *

def bfs_sqrt(N, bits):
    Q = [0]
    for k in range(bits):
        S = []
        for y in Q:
            for t in range(2):
                x = y + t * (2**k)
                if N % (2**(k+1)) == (x*x) % (2**(k+1)):
                    S.append(x)
        S, Q = Q, S
    return Q

def solve_csmith(N, e, c, max_bits, common_bits, beta=0.5):
    suffixes = bfs_sqrt(N, common_bits)
    for p0 in suffixes:
        k = common_bits
        l = max_bits-k
        print(f'{len(bin(N))=} {p0=} {l=} {k=} {beta=}')
        r = inverse(2**k, N)
        R = PolynomialRing(Zmod(N), name='x')
        x = R.gen()
        f = x + p0 * r
        roots = f.small_roots(X=2**l-1, beta=beta, all_roots=True)
        for p1 in roots:
            p1 = int(p1)
            p = int(p1*2**k + int(p0))
            p = gcd(N, p)
            if p <= 1:
                continue
            q = N // p
            phi = (q-1)*(p-1)
            d = int(inverse(e, phi))
            m = pow(c, d, N)
            flag = long_to_bytes(m)
            print(f'FLAG: {flag.decode()}')
            exit(0)


if __name__ == "__main__":
    for _ in range(20):
        N = int(input().strip().split('=')[1])
        e = int(input().strip().split('=')[1])
        c = int(input().strip().split('=')[1])
        input()

        nbits = N.bit_length()
        for pbits in range(500, 700, 10):
            qbits = nbits - pbits
            for common_bits in range(250, 350, 10):
                print(f'Trying pbits={pbits}, qbits={qbits}, common_bits={common_bits}')
                beta = qbits / nbits + 0.01
                solve_csmith(N, e, c, pbits, common_bits, beta)
```
